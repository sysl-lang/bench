# Fairness audit

An independent audit of the code and the harness of this repository (programs, `scripts/`, `awfy/`),
made 2026-11-20 on `dev` at 3c21092, before the first timing on sysl 0.12.0. It audits whether the
numbers can be trusted, not what they say. Each finding has a severity:

- **headline**: would change a headline claim (a geometric mean, or who is fastest on a program);
- **ratio**: would change one ratio by more than 5%;
- **disclosure**: changes no number materially, but a reader must be told.

Every headline and ratio finding is fixed on this branch; every disclosure is in README.md
("Known weaknesses of the plain columns", "Methodology, and what a reader should know") or in
`awfy/README.md`. No timing was taken: an urgent sysl 0.12.0 gate was running when the audit
started, and a merge train held marshal's queue when the fixes were done, so the size of A1 and A2
is unmeasured. Every changed program was rebuilt and verified through marshal (jobs 8057, 8074).

## Go

Go was removed with the other garbage-collected languages on 2026-11-18 (3c21092) and restored on
2026-11-20, alone, so that its column says where sysl stands against it (README rule 9). Its programs
were audited against the Game's Go entries and its published measurements (archive and
`performance/<program>.html`, fetched 2026-11-20) to the standard above. Go 1.27.4 (Homebrew, upgraded
from 1.27.3 for this). All ten programs were rebuilt and verified through marshal (job 8107): ten of
ten match the Game's output at the small size and C's hash at the timed size. No timing was taken.

| # | severity | where | finding | fix |
|---|---|---|---|---|
| G1 | disclosure, fixed | `scripts/lib.zsh` | **Thread count.** Every other program runs on one thread; an unset `GOMAXPROCS` lets Go run the collector's mark work on other cores in parallel, free wall-clock time no other language gets. | `GOMAXPROCS=1` exported for every Go run (verify and timing). The runtime's own service threads remain; their CPU time is in the CPU-time table. `GOGC` stays at its default, 100. |
| G2 | disclosure, fixed | `scripts/build.zsh` | **Build flags.** The Game builds Go with plain `go build` and `GOAMD64=v2` (its program pages); none of its Go entries uses `-gcflags=-B` or any other flag. Here Go was built for baseline arm64 (`GOARM64=v8.0`) while every other language builds for this processor. | `GOARM64=v8.7 go build`, this machine's level as `clang -mcpu=native` reads it (`+v8.7a`); no `-gcflags`, so bounds checks stay. `GOFLAGS` cleared. Its effect on speed is unmeasured (Go uses the level mostly for atomics and a few instructions). |
| G3 | disclosure | `programs/binarytrees/go` | **binary-trees recycles nodes through `sync.Pool`** (`binarytrees.go-6`, the Game's fastest single-threaded Go on CPU, 29.26 s against 61.36 for the plain-`&Node{}` `-7` used before). Every node is still its own heap object, obtained and returned one at a time, as C's are through `malloc`/`free`; the pool is Go's explicit free list. It checks and frees each tree in one walk, as `c-tuned` and `rust-tuned` do (D3). Allowed and stated in README; the asymmetry is against sysl. | — |
| G4 | headline (Go) | `programs/*/go`, SOURCES.md | **Seven of the ten Go programs were not Go's fastest entry.** Measured by the Game's CPU seconds (the cost that carries over to one thread): nbody `go` 7.03 where `-3` takes 6.40; fannkuch `-8` 46.27 where `-3` takes 33.33; binary-trees `-7` 61.36 where `-6` takes 29.26; mandelbrot `-8` 26.76 where `-4` takes 15.01; fasta `-8` 11.32 where `go` (`-1`) takes 3.75; k-nucleotide `-4` 30.77 where `-7` takes 28.88; and **pidigits used `math/big` (`-7`, 5.62) where Go's fastest, `-4`, calls GMP through cgo (0.83)** while every other language here uses GMP. | G5 | adaptation | `programs/{knucleotide,mandelbrot,pidigits}/go` | **Three fastest entries were adapted to our single-threaded rule and our sizes.** Each passes the Game's own checks under the Game's conditions. k-nucleotide `-7` rolls its key by shifting in `data[idx+i]`, which is the k-mer's new base when the goroutine stride is at least k, as it is on the Game; under our one-goroutine rule the stride is 1, so the base shifted in had to be the k-mer's last. mandelbrot `-4` computes each coordinate as `x*(2/size)`, which at our sizes (200 and 6,000) rounds some boundary pixels the other way from C's `2*x/size`, against which our timed size is checked (probed: not fused multiply-add, not `GOARM64`). pidigits `-4` prints whole lines of ten digits, as the Game's 10,000-digit run needs; our 27-digit check needs a padded last line. | Each adapted in the smallest way (the base shifted in, C's coordinate formula, computed once before the loop, and the last line padded as C pads it), stated in the file header and SOURCES.md. ## Checked and found sound

- **Thread count**: no program starts a thread. No build passes `-fopenmp`, so the C and Fortran
  OpenMP directives are inert; Rust, C++ and Swift programs were made sequential (SOURCES.md).
- **The sysl programs do the work.** Each sysl program was read against the C program: binary-trees
  allocates every node, leaves included (peak 50 MiB at 48 bytes a node, as FINDINGS §4 says),
  k-nucleotide builds a full table for every k, mandelbrot iterates to 50 with C's escape test,
  spectral-norm runs ten rounds of `A^T A`. `sysl-idiomatic` keeps every bounds check.
- **Floating point in the main suite**: sysl fuses exactly as clang's default `-ffp-contract=on`
  (`fp_contract.sysl`); no sysl program uses reassociation. The C and sysl arithmetic is the same.
- **Inputs**: every language reads the same generated file at each size, through hyperfine's
  `--input`, after the same three warm-ups; no build or I/O set-up is inside any timing.
- **The output checks can fail**: the small sizes compare with the Game's own files byte for byte
  and the timed sizes with a hash, and outputs depend on the work done (no program's output is
  computable without it, binary-trees' counts aside, whose sysl programs were read).
